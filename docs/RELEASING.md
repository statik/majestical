# Releasing

Pushing a `v*` tag runs `.github/workflows/release.yml`, which produces a
**draft** GitHub release. Nothing reaches users until someone publishes that
draft by hand, so a tag is safe to push and a bad build is safe to delete.

The draft receives:

- `Majestical.app.tar.gz` and a `.dmg` for `aarch64-apple-darwin` and
  `x86_64-apple-darwin`, built by `tauri-action`
- `latest.json`, the updater manifest, plus a `.sig` per bundle once the
  signing secrets exist (see [Updater keys](#updater-keys))
- `maj-<tag>-universal-apple-darwin.tar.gz` and `checksums.txt`, the
  command-line catalog as one universal binary
- `licenses.html`, the third-party crate licenses, generated by `cargo-about`
  from `about.toml` and `about.hbs`

macOS only. Windows and Linux artifacts, code signing, and notarization are
not in this phase.

## Cutting a release

1. **Bump the version in five places.** `scripts/version-sync.sh` is the list:
   `Cargo.toml`, `apps/desktop/package.json`,
   `apps/desktop/src-tauri/Cargo.toml`,
   `apps/desktop/src-tauri/tauri.conf.json`, and
   `apps/desktop/src-tauri/Cargo.lock`.

2. **Refresh the GUI lockfile.** Editing `src-tauri/Cargo.toml` does not
   rewrite the lockfile entry beside it; only a build does.

   ```bash
   cargo build --manifest-path apps/desktop/src-tauri/Cargo.toml
   ```

3. **Check the versions agree**, then commit and merge as usual.

   ```bash
   just version-sync
   ```

4. **Tag and push.** The tag must name the version just built — the workflow's
   first job checks this and stops the release if it does not. A `-rc1` style
   suffix is allowed, for exercising the pipeline without cutting a real
   release.

   ```bash
   git tag v0.2.0
   git -c credential.helper='!gh auth git-credential' \
     push https://github.com/statik/majestical.git v0.2.0
   ```

5. **Watch it, then publish.** A Tauri release build is slow; both matrix
   targets plus the CLI job take a while.

   ```bash
   gh run watch
   gh release view v0.2.0        # the draft, with its assets
   gh release edit v0.2.0 --draft=false
   ```

To abandon a release, delete the draft and the tag:

```bash
gh release delete v0.2.0 --yes
git -c credential.helper='!gh auth git-credential' \
  push --delete https://github.com/statik/majestical.git v0.2.0
```

## Updater keys

The app checks for updates on startup and offers a banner when one exists
(`apps/desktop/src/lib/updater.ts`). Updates are signed: Tauri verifies every
downloaded bundle against the public key compiled into the app, so the private
key is what makes shipping an update possible at all.

The public half lives in the repository, in
`apps/desktop/src-tauri/tauri.conf.json` under `plugins.updater.pubkey`, with
key ID `9D3AD6D3C4DA4E46`. Three things make the updater work, and they are
already in place:

1. `plugins.updater` in `tauri.conf.json` — the public key and the endpoint
   the app polls.
2. `bundle.createUpdaterArtifacts: true` in the same file. Without it the
   bundler produces no `.tar.gz`/`.sig` pair for the updater to download, and
   `latest.json` ships listing no platforms.
3. `.plugin(tauri_plugin_updater::Builder::new().build())` in
   `apps/desktop/src-tauri/src/lib.rs`. This line and the config in step 1
   must stay together — the updater's config has no default for `pubkey`, so
   a registered plugin with no `plugins.updater` block fails to deserialize
   its configuration and the app exits on startup instead of opening a
   window.

### The private key

The private half lives in two repository secrets, `TAURI_SIGNING_PRIVATE_KEY`
and `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. Both are set (`gh secret list`).
`release.yml` passes them to `tauri-action`; no workflow change is needed.

**Nothing has yet proved that those secrets hold the private half of the
public key above.** Only a real build can: it signs the bundles, and the
`.sig` files it produces verify against the embedded key or they do not. The
first tagged build is that proof — check that the draft has a `.sig` beside
each bundle and that `latest.json` lists both platforms. Until then, treat
the pairing as unconfirmed.

If a release ever runs without the secrets, it still succeeds: the bundles
are simply unsigned, and `latest.json` lists no platforms. That is the
designed degradation, not a failure — but do not publish such a draft, since
installed apps cannot verify anything in it.

To regenerate the keypair from scratch:

```bash
cd apps/desktop && pnpm tauri signer generate -w /tmp/majestical-updater.key
gh secret set TAURI_SIGNING_PRIVATE_KEY < /tmp/majestical-updater.key
gh secret set TAURI_SIGNING_PRIVATE_KEY_PASSWORD   # the password chosen above
trash /tmp/majestical-updater.key
```

A new keypair means replacing `plugins.updater.pubkey` in the same commit.
Losing the private key means no existing installation can ever be updated
again; a new key only reaches users who reinstall by hand.
