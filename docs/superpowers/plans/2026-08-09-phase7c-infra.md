# Phase 7C — Infra Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Failing service calls carry their notices; the TS wire layer is pinned against Rust with committed fixtures; the Rust suite runs on a `{macos, ubuntu}` CI matrix with Apple-only derivations honestly absent off-macOS; two zizmor auditor findings closed.

**Architecture:** A `ServiceError::WithNotices` carrier variant attached inside `crates/services` at the four sync-verb boundaries (the only verbs whose local sink drops on `Err`); each head splits the carrier once and renders notices through its existing channel. Wire fixtures are generated by a Rust test and type-checked under `api.ts`. Target-gating is `cfg(target_os = "macos")` on `crates/index`'s three Apple seams (Vision/PDFKit modules, CoreML EP, `sips`), with planner-level exclusion so absent capabilities are named, never silently zero.

**Tech Stack:** Rust (thiserror, serde, cargo), Tauri 2 + Svelte 5 (vitest, svelte-check), GitHub Actions, zizmor.

**Spec:** `docs/superpowers/specs/2026-08-09-phase7c-infra-design.md`

**Process reminders (user-mandated):** no Claude-Session trailers in commits; plain git (no submitting-changes skill); implementers stage only their own files, never `git add -A`; `cargo-mutants` runs FOREGROUND, one at a time; `git fetch origin` before reviewing; `trash`, never `rm -rf`; zero warnings.

**Spec deviations already known (record in the spec's as-built section at close):**
- The attach seam applies to the **four sync verbs** (`status`, `locations_list`, `push`, `pull`), not "~30 verb boundaries" — the survey showed every other verb's sink lives on `App`/head-side and survives the `Err` path (`with_app` in `crates/cli/src/main.rs:571-584` already drains on error).
- MCP failure notices ride as **leading text content blocks** on the `isError` result, not a `notices` field — `rmcp`'s `CallToolResult::error(Vec<ContentBlock>)` is the error constructor; structured content is the success-path shape.
- The rust-toolchain finding is zizmor `superfluous-actions` (the action duplicates the runner's rustup), not a missing SHA pin — the fix is replacing the action with a `rustup` script step.

    /// Wraps an `Err` leaving a verb while this sink still holds
    /// diagnostics, so the failure carries them instead of dropping them —
    /// the `Err`-path counterpart of folding `drain()` into an `Ok`
    /// outcome's `notices` field. `Ok` passes through untouched, as does an
    /// `Err` when the sink is empty. Wrapping an error that is already a
    /// carrier appends to it rather than nesting.
    pub fn attach_on_err<T>(
        &self,
        result: Result<T, crate::error::ServiceError>,
    ) -> Result<T, crate::error::ServiceError> {
        use crate::error::ServiceError;
        match result {
            Ok(value) => Ok(value),
            Err(err) => {
                let drained = self.drain();
                if drained.is_empty() {
                    return Err(err);
                }
                Err(match err {
                    ServiceError::WithNotices { mut notices, source } => {
                        notices.extend(drained);
                        ServiceError::WithNotices { notices, source }
                    }
                    other => ServiceError::WithNotices {
                        notices: drained,
                        source: Box::new(other),
                    },
                })
            }
        }
    }
```

/// Splits a `WithNotices` carrier: prints its notices to stderr — the same

    result.map_err(|err| match err {

/// The failure-path analogue of [`with_notices`]: a tool error whose
/// leading content blocks are the notices the failing call collected — one
/// text block per line, in push order — followed by the inner error's full
/// Display chain. MCP has no stderr; these blocks are the only channel a
/// failure's warnings have. Non-carrier errors get the plain
/// [`tool_error`] shape with zero leading blocks.
fn tool_error_split(err: majestical_services::error::ServiceError) -> CallToolResult {
    use majestical_services::error::ServiceError;
    let (notices, err) = match err {
        ServiceError::WithNotices { notices, source } => (notices, *source),
        other => (Vec::new(), other),
    };
    let mut blocks: Vec<ContentBlock> =
        notices.into_iter().map(ContentBlock::text).collect();
    blocks.push(ContentBlock::text(format!(
        "{:#}",
        anyhow::Error::from(err)
    )));
    CallToolResult::error(blocks)
}
```

```rust
/// The one error shape every command returns: the full anyhow/`ServiceError`
/// Display chain (where the remedy text already lives, same rule as
/// `maj mcp`'s `tool_error`), plus any notices the failing call collected —
/// the failure-path counterpart of the outcome structs' `notices` field,
/// with the same absent-when-empty wire contract.
#[derive(Debug, Serialize)]
pub struct CommandError {
    pub message: String,
    #[serde(skip_serializing_if = "Vec::is_empty")]
    pub notices: Vec<String>,
}

impl CommandError {
    fn new(message: impl Into<String>) -> Self {
        Self {
            message: message.into(),
            notices: Vec::new(),
        }
    }
}

impl<E: Into<anyhow::Error>> From<E> for CommandError {
    fn from(err: E) -> Self {
        let err: anyhow::Error = err.into();
        let (notices, err) = match err.downcast::<ServiceError>() {
            Ok(ServiceError::WithNotices { notices, source }) => {
                (notices, anyhow::Error::from(*source))
            }
            Ok(other) => (Vec::new(), anyhow::Error::from(other)),
            Err(err) => (Vec::new(), err),
        };
        Self {
            message: format!("{err:#}"),
            notices,
        }
    }
}
```

/**
 * The wire shape of a rejected command — `commands::CommandError`.
 * `notices` is absent (not `[]`) when the failing call collected none.
 */
export interface CommandError {
  message: string;
  notices?: string[];
}

/** The notices a rejected command carried, `[]` when none. */
export function errorNotices(error: unknown): string[] {
  if (typeof error === "object" && error !== null && "notices" in error) {
    const { notices } = error as { notices: unknown };
    if (
      Array.isArray(notices) &&
      notices.every((n) => typeof n === "string")
    ) {
      return notices;
    }
  }
  return [];
}

/// Recursively refuses empty arrays, empty objects, empty strings, and

fn assert_fully_populated(name: &str, value: &serde_json::Value) {

        }
        serde_json::Value::Object(map) => {
            assert!(!map.is_empty(), "{name}: empty object pins nothing");
            for (key, item) in map {
                assert_fully_populated(&format!("{name}.{key}"), item);
            }
        }
        serde_json::Value::String(s) => {
            assert!(!s.is_empty(), "{name}: empty string pins nothing");
        }
        serde_json::Value::Null => panic!("{name}: null pins nothing"),
        serde_json::Value::Bool(_) | serde_json::Value::Number(_) => {}
    }
}

fn check_or_update(name: &str, value: &serde_json::Value) {
    assert_fully_populated(name, value);
    let path = fixtures_dir().join(format!("{name}.json"));
    let rendered =
        serde_json::to_string_pretty(value).expect("fixture serializes");
    if std::env::var_os("MAJ_UPDATE_FIXTURES").is_some() {
        std::fs::write(&path, format!("{rendered}\n")).expect("write fixture");
        return;
    }
    let committed = std::fs::read_to_string(&path).unwrap_or_else(|_| {
        panic!(
            "missing fixture {} — regenerate with \
             MAJ_UPDATE_FIXTURES=1 cargo test --test wire_fixtures",
            path.display()
        )
    });
    assert_eq!(
        committed.trim_end(),
        rendered,
        "wire shape drifted from {} — if the Rust change is intentional, \
         regenerate with MAJ_UPDATE_FIXTURES=1 and update api.ts to match",
        path.display()
    );
}

#[test]

    // One (name, value) pair per api.ts interface. CommandError, complete:
    let command_error =
        CommandError::from(majestical_services::error::ServiceError::WithNotices {
            notices: vec!["a warning the failing call collected".to_string()],
            source: Box::new(
                majestical_services::error::ServiceError::NoCatalog {
                    root: std::path::PathBuf::from("/fixtures/catalog"),
                },
            ),
        });
    check_or_update(
        "command_error",
        &serde_json::to_value(&command_error).expect("serialize"),
    );
    // The remaining pairs — app_status, search_outcome, asset_detail,
    // volumes_outcome, saved_searches — are struct literals built
    // field-by-field: every field on these types is a pub wire field (read
    // each definition in crates/services / commands.rs and populate every
    // one). assert_fully_populated refuses any shortcut: an empty Vec,
    // None-omitted Option, or empty string fails the test by design.
}
