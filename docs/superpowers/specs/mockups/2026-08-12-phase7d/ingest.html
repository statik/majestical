Ingest — one verified job, three honest states

Single job with live progress, per your scope call. The surface is a board that walks left-to-right: source → destinations → plan → run. Nothing copies before the plan is on screen, progress is per-file and per-byte off the new engine seam, and a crash turns into a resume banner, not a lost run. The queue waits for a later phase.

  • ·On surface load the GUI checks the transfer journal; an incomplete run becomes the amber resume banner. The completion card states exactly what exists: placed counts from real rows, per-destination MHL generations, failures quarantined with reasons — never a green checkmark over a partial truth.

My read: this is the OffShoot claim made honest in Majestical's idiom — plan first, verify always, resume anything, and the GUI shows the same run ids and outcome rows the CLI and MCP see. The only new machinery is the progress seam; everything else rides the existing engine, journal, and outcome structs.
